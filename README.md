# Coverlens

Coverlens measures whether an existing test suite covers the requirements of a
new feature. It reads a spec (user stories with acceptance criteria, in
markdown) and optionally a test suite (.xlsx), and writes a gap report. It
never generates tests.

## Install

```
uv sync
```

## Run

```
uv run coverlens run \
  --domain domains/ott_web/pack.yaml \
  --spec data/ott_web/user_stories.md \
  --suite data/ott_web/test_cases.xlsx \
  --out out/ --fake
```

`--fake` uses an offline word-overlap judge instead of the LLM. Without
`--suite`, every requirement is reported as a gap.

To use the LLM judge, run Ollama locally, pull the model once and drop `--fake`:

```
ollama pull llama3.1:8b
uv run coverlens run --domain ... --spec ... --suite ... --out out/
```

To use a model on Ollama Cloud instead (free plan, starter models only), copy
`.env.example` to `.env` and put your key from ollama.com/settings/keys there:

```
OLLAMA_API_KEY=your-key
```

`.env` is git-ignored (a contract test fails if it stops being ignored), so the
key is never committed. Then:

```
uv run coverlens run ... --ollama-url https://ollama.com --model gpt-oss:120b --num-predict 4096 --no-tier2
```

The key is looked up in this order: `--api-key-file`, the `OLLAMA_API_KEY`
environment variable, then `.env` in the current directory. It is sent only as
a request header; it is never written to the cache, the report or an error
message. Thinking models spend reply tokens on reasoning, so give them a higher
`--num-predict`. With a strong judge like this, `--no-tier2` skips the
word-overlap rule, which then makes more mistakes than the judge.

Options: `--model` (default `llama3.1:8b`), `--ollama-url` (default
`http://127.0.0.1:11434`), `--cache-dir` (default `.coverlens_cache/`),
`--num-ctx`, `--num-predict`, `--no-tier2`, `--api-key-file`. Every LLM reply is
cached by a hash of the full request, so rerunning unchanged input makes no LLM
calls; each run prints its calls, tokens and seconds.

## Output

- `out/coverage_report.xlsx`
  - **Gap report**: one row per acceptance criterion with its status
    (covered / gap / uncertain), the deciding tier, cited cases, candidates and
    rationale.
  - **Coverage**: summary, per-story rollup, orphan cases (claim and cover
    nothing), mis-referenced cases (claim a criterion they do not cover) and,
    when the pack declares `pairwise`, dimension pair coverage: which value
    pairs (e.g. Browser x Network) the suite exercises, the missing pairs, and
    how many more combinations would cover them.
- `out/coverage_report.json`: the same report as JSON.

## How it decides

1. **Tier 1** (refs, tags, BM25): concludes only "certain gap" or "orphan
   case", never "covered", and hands each other criterion a short list of
   candidate cases.
2. **Tier 2** (rules): a case containing at least `tier2.min_overlap` of a
   criterion's terms covers it, with no LLM call. It never concludes "gap".
   Off with `--no-tier2`.
3. **Tier 3**: an LLM judge on Ollama (local Llama by default, or a cloud
   model), which must cite case IDs from the candidates it was shown; an
   invalid reply is retried once and otherwise becomes "uncertain". `--fake`
   replaces it offline.

Everything domain-specific (column names, dimensions, tags, glossary,
thresholds, pairwise constraints) lives in a domain pack.

## Domains

| Domain | Pack | Data | Role |
|---|---|---|---|
| OTT web player (fictional *Streamly*) | `domains/ott_web/pack.yaml` | `data/ott_web/` (52 criteria, 57 cases) | development set |
| Insurance claims (fictional *Quillmoor Mutual*) | `domains/claims/pack.yaml` | `data/claims/` (100 criteria, 120 cases) | held-out test set |

All data is synthetic. `data/` is read-only; `data/claims/` is generated by
`eval/datasets/build_claims.py`, and contract tests pin every file's hash.

## Evaluate

```
uv run python -m eval --fake                      # ott_web, offline
uv run python -m eval --dataset claims --fake     # claims, offline
```

Eval takes the same judge options as `run`. It prints gap and coverage
precision/recall, citation accuracy, candidate recall, orphans and decoys with
95% bootstrap intervals, and exits 1 if the canary fails (Tier 1 must never
call a covered requirement a gap). Only `eval/` reads the answer keys.

- `--save FILE` stores a run; `--compare FILE` says whether a change against a
  saved run is a real gain, a real loss or noise (paired bootstrap), and lists
  the criteria it fixed and broke. Saved runs live in `eval/baselines/`.
- `--disagreements` lists where the pipeline and the key disagree, with the
  evidence, for a human to review; decisions go in `eval/reviews/<dataset>.yaml`
  and eval also scores against the reviewed key.

## Results

Measured 2026-10-07; details in `docs/experiments/`.

| Configuration | ott_web (52) | claims, held-out (100) |
|---|---|---|
| `llama3.1:8b` local, Tier 2 on | 50/52 | 81/100 |
| `gpt-oss:120b` on Ollama Cloud, `--no-tier2` | 51/52 (98%) | **95/100 (95%, CI [90%, 99%])** |

With `gpt-oss:120b` every "gap" verdict was right on both domains; every
remaining error is a "covered" verdict on a criterion that a case only partly
checks. All remaining disagreements were reviewed by a person and the keys
upheld. Prompt rewording, majority voting and condition-by-condition judging
were measured and did not help (`docs/experiments/`).

## Limits

- Tested on synthetic data only; the answer keys were written by an AI and
  only their disagreements with the pipeline were reviewed by a person.
- About 5% of criteria on the held-out set were wrongly called covered, which
  hides real gaps: review important "covered" verdicts.
- Pairwise coverage reads the suite's dimension columns, which describe the
  environment a case runs in, not always what it checks.
